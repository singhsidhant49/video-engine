# MEDIA_EDITORIAL migration audit

Generated: 2026-10-01 (Asia/Calcutta)

1. **Architecture audit.** The old production decision was storyboard shot → coverage representation/family → variant → family JSX. Solved M14–M16 infrastructure existed, but procedural families could still be chosen by normal production and solved-media failures could fall back to `PhotoShot`. The new production entry point resolves one visual policy and routes normal runs through media selection, `EditorialVisualBeat`, solved media composition, `MediaShotPlan`, preflight, quality gate, and Remotion execution.
2. **Files changed.** The migration adds centralized visual-mode configuration, editorial-beat and media-shot-plan schemas/planning, production routing, typed timeline registries, mode-aware cache invalidation, expanded continuity metrics, benchmark rendering, tests, and this audit. Legacy family files are retained.
3. **Old production path.** `chooseFamily()` could prefer process, chart, comparison, statement, document, UI, code, diagram, or map based on coverage and scene kind. React family components then performed presentation work.
4. **New MEDIA_EDITORIAL path.** `createFacelessVideo()` defaults to `MEDIA_EDITORIAL`; procedural asset preferences are converted into real-media requests; realized shots are image/video/montage; every accepted shot must compile as solved media; failed/weak shots stop production instead of silently selecting a procedural renderer.
5. **Routing changes.** `resolveVisualPolicy()` is the single authority for `USE_MEDIA_EDITORIAL`, `ENABLE_PROCEDURAL_GRAPHICS`, and `ENABLE_LEGACY_VISUAL_FAMILIES`. `LEGACY_PROCEDURAL` is available via CLI or API override. JSX does not inspect environment flags.
6. **MediaShotPlan schema.** The strict plan persists editorial purpose, selected asset/type/role, timing, composition strategy, crop and object position, camera path/reason, overlay, subtitle and annotation plans, transitions/reasons/anchors, quality tier, read/final-hold budgets, rejected alternatives, verdict, and repair history.
7. **Asset-intelligence propagation.** Width, height, aspect ratio, focal point, subject/face/protected bounds, safe text/negative-space regions, crop fitness/slack, busyness, quality tier, native motion, evidence strength, and unknown fields flow into the solved spec. Unknown subject coordinates are no longer synthesized from focal points.
8. **Crop/reframe implementation.** The solver computes cover crop, focal object position, subject projection, caption clearance, camera endpoints, and swept-path preflight before render. Portrait/landscape incompatibility can trigger layered/editorial split or alternate-asset requests.
9. **Image behavior.** Full bleed with subtitles is the no-text default. Stills are static unless an upstream editorial camera request exists. Overlay-bearing and poor-crop images can use a restrained split/layer treatment.
10. **Video behavior.** Video uses the same focal/crop geometry as images. Native-motion video forces synthetic camera behavior to `STATIC`; Remotion receives solved object position and camera values.
11. **Camera behavior.** Supported solved behaviors are static, subtle push/pull, focal pan, detail crop, reframe/match move. Push is 1.000→1.025. Each non-static `MediaShotPlan` has a reason; static has no invented justification.
12. **Subtitle behavior.** Production media mode uses phrase captions, 4–8-ish words according to format limits, one/two lines, direct replacement or short fade, solved geometry, subject-aware alternate placement, and Shorts interaction-safe margins.
13. **Text overlay behavior.** Ordinary shots default to no overlay. Minimal contextual chapter/evidence/stat text is permitted. Exact text geometry and line breaks are solved before JSX.
14. **Chapter behavior.** Chapter copy uses relevant background media, a subtle gradient scrim, simple typography, and no standalone decorative title-card family.
15. **Annotation behavior.** Direct labels/pointers compile into solved text and SVG geometry linked to an asset region and narration phrase.
16. **Montage behavior.** Montage exists only with multiple assets. Items are cut on available phrase boundaries (fallback: evenly spaced), with semantic progression reasons and active ranges persisted.
17. **Cut/transition behavior.** Media production returns clean cuts by default. No automatic effect rotation or opening/ending fade-to-black is added. Match anchors remain explicit in plans.
18. **Shot timing logic.** Existing narration-aligned timing remains authoritative; fixed three-second media switching is absent. Read and final-hold budgets are persisted.
19. **Continuity logic.** Diagnostics track media/layout/camera runs, repeated assets, caption positions, transition distribution, shot-duration statistics, rapid cuts, long static holds, and media-type runs without forcibly mutating valid repeated cuts/static shots.
20. **QA/preflight.** Solved scenes are inspected at frame 0, quarter states, final state, and event boundaries. Media quality checks include occupancy, subject/caption collision, crop treatment, relevance/evidence, synthetic motion over video, text coexistence, mobile safety, and alternate-asset status.
21. **Repair/reselection.** Up to four candidates are considered. Rejections record bad crop, low resolution, or missing mobile-safe crop. Remaining quality failures stop `MEDIA_EDITORIAL`; legacy fallback is only allowed in explicit legacy mode.
22. **Debug artifacts.** Runs persist `editorial-visual-beats.json`, `media-shot-plan.json`, media specs/compositions, solved scenes, motion plans, preflight, quality reviews, continuity diagnostics, fallbacks, and performance.
23. **Tests.** `npm test` passes 152/152. New migration tests cover default/legacy routing, procedural-to-media requests, no procedural realization in media mode, static default, strict beat/shot-plan contracts, solved crop/caption/cut rationale, chapter readability, face protection, and native-video behavior. Existing M14/M15/M16 regression coverage remains.
24. **Full landscape render path.** `npm run render:media-editorial` builds a 60-second, 12-shot 1920×1080 media-only benchmark with hard cuts and solved geometry. Output: `renders/media-editorial-benchmarks/landscape.mp4`.
25. **Full Shorts render path.** The same command builds a 36-second, 9-shot 1080×1920 edit with vertical focal crops and phone-safe captions. Output: `renders/media-editorial-benchmarks/shorts.mp4`.
26. **Timestamped human review.** See `docs/media-editorial-human-review.md`. The report explicitly distinguishes renderer/composition success from semantic asset and narration limitations.
27. **Before/after observations.** The new route removes dashboard/process/chart/card families from normal production, makes real media occupy the frame, defaults to cuts/static, and moves crop/caption decisions upstream. The benchmark looks materially less template-driven, but some split/stat frames still feel like designed layouts and several source assets repeat subject matter.
28. **Performance.** Timeline artifacts include planning, media solve, camera solve, and preflight milliseconds; full render manifests include render time and output size. The final corrected benchmark rendered landscape in 123.9 seconds and Shorts in 74.8 seconds on this machine.
29. **Known limitations.** The deterministic benchmark uses existing local provider assets and ambient music, not a newly recorded/TTS narration, so it validates full temporal rendering and caption playback but not final voice-sync quality. Existing assets have uneven semantic specificity and include repeated finance architecture. Face detection depends on provider metadata; the migration does not add a new vision model. The code is not claimed production-ready solely from passing tests/renders.
30. **Exact next step.** Run two new end-to-end provider-backed topics through `createFacelessVideo()`—one 60–90s landscape and one 30–60s Short—with real TTS/Whisper alignment, then replace or re-rank every asset flagged in the human report and repeat playback review before enabling publishing.
